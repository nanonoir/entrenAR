# EntrenAR — Agent Guide

EntrenAR is a full-stack fitness and sports ecommerce platform built as a reusable commercial base and portfolio project. It pairs a high-performance Next.js storefront with an administrative CRM panel and a standalone NestJS backend modular monolith with PostgreSQL and Prisma ORM.

## Operational Stack Summary

- **Frontend Framework**: Next.js 16.2.4 (App Router), React 19.2.4, TypeScript 5, Tailwind CSS 4 (`@tailwindcss/postcss`)
- **State & Forms**: Zustand 5.0.12, React Hook Form 7.78.0 + Zod 4.4.3 (`@hookform/resolvers`)
- **Backend Framework**: NestJS 11.1.16 modular monolith (under `backend/`), Node.js runtime
- **Database & ORM**: PostgreSQL with Prisma 7.6.0 (`@prisma/client`, `@prisma/adapter-pg`)
- **Backend Auth & Security**: JWT (`@nestjs/jwt`), Bcrypt, RBAC guards, Helmet
- **Object Storage**: Cloudflare R2 / AWS S3 SDK (`@aws-sdk/client-s3`) for product catalog media
- **Testing & Quality**: Jest 30 (backend unit/integration/e2e), Playwright 1.61 (E2E), ESLint 9

*Note: Technical manifests (`package.json`, `backend/package.json`) remain the authoritative source for dependencies.*

## Essential Commands

### Development & Builds
- `npm run dev` — local Next.js frontend development.
- `npm run build` — frontend production build.
- `npm run build:backend` — backend production build.
- `npm run build:all` — frontend and backend production builds.

### Quality & Verification
- `npm run lint` — frontend linting.
- `npx tsc --noEmit` — root TypeScript compiler check.
- `npm run verify:frontend-acceptance` — frontend boundary and adapter test harness.

### Backend Testing
- `npm run test:backend` — backend unit tests.
- `npm run test:backend:integration` — backend integration tests.
- `npm run test:backend:e2e` — backend end-to-end tests.

### Database Operations
- `npm run db:migrate` — apply backend Prisma migrations.
- `npm run db:seed` — run backend database seeder.

## Critical Invariants & Project Conventions

1. **Backend Authority**: The frontend expresses intent only. The NestJS backend authenticates, authorizes, validates calculations with Zod, and executes transactional persistence. Never trust client-side prices, totals, or stock.
2. **Prisma Isolation**: Prisma Client is strictly confined to `backend/`; it is never imported or accessed in the Next.js frontend tree.
3. **Data Layer Flow**: Storefront and admin access backend services via `src/lib/api` adapters, not scattered `fetch()` calls or redundant Next.js route proxies.
4. **Delivery Policy**: Conventional commits and ExecPlans (`docs/exec-plans/`) form the delivery record. Do not create or link GitHub issues unless explicitly requested.
